# 社区版组织目录与权限矩阵

## 实施范围

当前实现包括组织目录、钉钉企业后台配置与手动同步、本地账号受控绑定、部门查询、业务角色映射、表级追加矩阵、权限预览、字段/记录限制和实时发送前复核。本地已完成企业同步；真实员工的角色、矩阵和限制须由管理员另行配置，不会在部署时自动授权。

组织目录及权限属于 Nest 应用层，不进入 v2 Table 领域。下文保留各阶段设计演进；当前首版的细粒度支持清单与限制以第 11—14 期知识库记录为准。

## 身份模型

| 模型                | 职责                                                                                                                    |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| DirectoryConnection | 来源与企业标识。钉钉使用 provider=dingtalk、tenantId=企业 corpId；数据库配置的 AppSecret 加密存储；环境配置作为只读来源 |
| DirectoryDepartment | 来源企业内唯一的部门标识、名称、父部门标识与停用时间                                                                    |
| DirectoryMember     | 来源企业内唯一的员工标识、可选 unionId、可选本地 userId、来源角色标识与停用时间                                         |
| DirectoryMembership | 员工与部门的多对多关系；复合外键禁止跨连接关联                                                                          |
| DirectorySyncRun    | 同步执行状态、起止时间、处理数量与脱敏错误码                                                                            |

外部 ID 以字符串保存。稳定键为 `(connectionId, externalId)`，不以名称、邮箱或手机号识别人。部门变更、改名和离职重入保留本地目录 ID。unionId 只作身份属性，不假设它在所有来源或企业间全局唯一。同一企业内一个本地账号最多绑定一名员工；员工尚未绑定账号也可同步。

首次绑定须由管理员确认，或由后续实现的、验证企业和来源主体的登录流程完成。同步数据不能携带 userId、isAdmin、roleName 等本地授权属性。企业级管理员身份、空间管理员身份和同步来源的管理员身份分别管理。

## 同步契约

`directory-snapshot.ts` 定义内部标准化输入，供后续来源适配器使用，不直接作为外部公开 HTTP 请求体。

- 全部部门、员工和角色分页拉取完成后，适配器才可设置 `complete: true`。仅凭该字段不能证明远端结果完整，完整性检查由适配器负责。
- 快照禁止重复员工和部门标识、缺失父部门、部门循环、悬空或重复的成员关系。每个在职员工至少属于一个部门；来源根节点须标准化为 parentExternalId=null。
- 来源角色仅保存 externalRoleIds；后续角色目录与显式映射规则负责解释这些标识，不直接写入 Collaborator.roleName。
- 校验完成后，同一连接内串行同步；目录更新、关系替换、失效处理与成功状态须在一个事务内提交。失败保留已有目录，并另行记录脱敏失败状态。
- 仅经确认完整的全量同步可以将缺失成员、部门标记为停用。增量事件缺失对象不表示删除；它需要独立的事件契约。
- 首次及异常大规模减员需要提供可审阅的差异，避免接口授权范围缩小被误判为批量离职。该检查属于后续同步服务。
- 不物理删除离职身份。撤销该身份在本企业的成员关系和派生授权；只有明确由该企业托管的本地账号，才适用全局禁用策略。其他企业身份与本地独立授权不得被连带禁用。

## 权限接入规则

当前空间和数据库角色保持现有行为。后续在受信任的服务端请求上下文加载已绑定、在职且连接启用的目录身份，再解析部门主体。

部门权限是否包含子部门必须作为显式规则；不能单凭部门树自动获得数据库访问。授权主体使用本地用户 ID、部门目录 ID 和本地业务角色 ID，不能使用跨企业可能重复的钉钉 ID。现有 `Collaborator` 的部门主体预留只是接入点，不能在目录迁移后立即启用。

员工调部门、离职、连接禁用或角色映射撤销时，必须同步使会话中的派生权限和权限缓存失效。表级矩阵实施前先确定现有空间/数据库角色的继承、管理员保底访问与多角色合并规则，避免仅隐藏前端入口。

## 后续验收

1. 管理员配置钉钉企业连接，凭据采用受保护配置或加密存储，响应与日志不回显密钥。
2. 手动同步支持预览差异、幂等更新、分页失败回滚、同连接并发互斥和同步日志。
3. 绑定本地账号后，组织查询按当前用户的企业范围返回数据；未绑定用户不能浏览企业通讯录。
4. 测试调部门及离职后的访问撤销、跨企业 ID 碰撞与现有本地用户行为。
5. 以这些身份为授权主体实现表级矩阵及后端强制校验。

## 钉钉连接与手动同步（后端）

先按部署流程应用 `20261109000000_add_organization_directory` 迁移并重新生成 Prisma Client。后端从环境变量读取连接，默认空数组表示未启用：

```dotenv
BACKEND_DINGTALK_DIRECTORY_CONNECTIONS='[{"corpId":"ding-your-corp-id","name":"企业名称","appKey":"your-app-key","appSecret":"your-app-secret"}]'
```

配置由部署方保管，不提交真实凭据到仓库。corpId 与凭据的归属须由部署方核实；token 响应不回传企业标识，当前无法独立核验二者对应关系。使用企业内部应用，授予根部门及全企业的部门、员工、角色及角色成员读取权限；授权范围受限时不要将预览视为完整企业名册。来源角色当前仅保存 ID，没有角色名称目录。

以下接口要求已登录的实例管理员；使用令牌时还须具备 `instance|update` scope。空间管理员不可调用：

| 方法 | 路径                                               | 输入与输出                                                          |
| ---- | -------------------------------------------------- | ------------------------------------------------------------------- |
| GET  | `/api/admin/organization/dingtalk/connections`     | 返回 corpId、名称及 provider，不返回凭据                            |
| POST | `/api/admin/organization/dingtalk/preview`         | `{ "corpId": "..." }`；返回新增、变更、停用明细及 previewToken      |
| POST | `/api/admin/organization/dingtalk/sync`            | `{ "corpId": "...", "previewToken": "预览返回的值" }`；返回同步日志 |
| GET  | `/api/admin/organization/dingtalk/runs?corpId=...` | 最近 50 次同步日志                                                  |

审阅预览后提交 token；执行时重新读取远端，快照、本地目录或绑定变化时返回 409，需重新预览。token 绑定 corpId，是差异指纹，不替代管理员认证。预览登记连接元信息，不写入部门或成员。

部门树、员工分页、角色列表和角色成员全部获取成功并校验后才允许写入。单次拉取限制请求数量及总耗时，每次 HTTP 请求单独超时。应用使用 PostgreSQL 事务级 advisory lock，并发应用返回 409；目录与成功日志在同一事务提交，失败日志单独保存脱敏错误码。

同步保留原有 userId 绑定，缺失员工标记停用并移除部门关系及来源角色。当前没有目录派生授权，不修改本地用户的登录状态或独立协作者授权；目录查询已实时检查绑定状态；业务资源的访问撤销留到权限接入阶段实现。

已提供管理员后台页面，尚未提供定时任务。首次及大规模减员须审阅差异，当前无自动比例阈值拦截。进程异常终止可能留下 running 日志，尚无后台恢复器。真实企业联调尚未执行。

接口参考：[企业内部应用 accessToken](https://open.dingtalk.com/document/orgapp/obtain-the-access_token-of-an-internal-app)、[部门列表](https://open.dingtalk.com/document/orgapp/obtain-the-department-list-v2)、[部门用户详情](https://open.dingtalk.com/document/orgapp/queries-the-complete-information-of-a-department-user)。

## 受控账号绑定与组织查询（后端）

实例管理员可以查询所有同步员工（包括未绑定和已停用员工），并显式绑定本地账号：

| 方法 | 路径                                           | 输入与行为                                                                        |
| ---- | ---------------------------------------------- | --------------------------------------------------------------------------------- |
| GET  | `/api/admin/organization/dingtalk/listMembers` | 查询参数 corpId、可选 search、skip、take，返回员工、当前账号和部门；take 最大 100 |
| POST | `/api/admin/organization/dingtalk/bindMember`  | body 为 corpId、memberId、userId、expectedUserId；memberId 是本地目录员工 ID      |

首次绑定示例：

```json
{
  "corpId": "ding-your-corp-id",
  "memberId": "directory-member-local-id",
  "userId": "existing-local-user-id",
  "expectedUserId": null
}
```

解绑时 userId 设为 null，expectedUserId 填当前绑定的本地账号 ID。替换已有绑定必须先解绑。员工及本地账号必须有效、连接必须启用才能新增绑定；停用身份和禁用连接仍可解绑。绑定接口与同步应用共用企业锁，绑定值变化或同企业账号已被其他员工占用时返回 409，不自动覆盖。成功操作向现有 AuditScope 管道发出绑定变更事件，包含变更前后账号 ID。接口不创建本地账号、不按邮箱自动认领，也不授予任何业务角色。

原有组织接口现在返回当前登录用户已绑定企业的真实目录：

- `GET /api/organization/me`：返回企业 id、名称；尚无企业管理员角色模型，isAdmin 固定为 false。实例管理员通过独立的管理接口操作目录。
- `GET /api/organization/department`：支持 parentId、search、includeChildrenDepartment；默认列根部门，指定父部门默认只列直接子部门。搜索默认遍历全部下级，可显式传 false 限制范围。
- `GET /api/organization/department-user`：支持 departmentId、search、includeChildrenDepartment、skip、take。返回已绑定且有效的本地用户 ID、名称、邮箱、头像和部门路径，排除未绑定员工、离职员工及已停用或删除的本地账号。指定部门时默认仅查直接成员，递归查询需传 true；未指定部门时查所选企业全部有效绑定账号。分页最多 100，total 与列表在同一数据库快照内读取。

以上三个接口均接受可选 organizationId，其值是 DirectoryConnection 的本地 ID，不是 corpId。请求方必须在指定企业拥有有效绑定，即使实例管理员也不绕过此检查。无参数时按 connectionId 升序选择第一个有效企业，保持现有单企业 SDK 的使用方式；多企业调用方须显式传 organizationId，后续界面会提供切换入口。

查询每次实时检查绑定、员工、本地账号及连接状态，不依赖会话中的组织缓存。未绑定用户的默认查询仍返回 null 或空列表；显式请求无权企业返回 403，传入其他企业或停用部门的 ID 返回 404，不回退为全企业查询。部门返回本地稳定 ID，path/pathName 包含从根到当前部门的完整路径。

本阶段不向授权上下文写入部门、不修改 `/auth/user/me` 的 organization 字段，也不开放部门邀请或部门派生授权。因此既有分享入口尚未自动显示组织邀请；避免目录功能先行启用尚未实现的部门授权。后续管理界面与权限矩阵会完成相应接入。

## 管理页面

实例管理员从后台侧栏的“钉钉组织目录”进入 `/admin/directory`。页面通过 SSR 校验管理员身份，客户端也只为管理员查询数据；后台接口继续强制检查 `instance|update`。

- 企业连接由服务端配置提供；未配置时显示部署提示，不在浏览器采集或展示应用密钥。
- 选择企业后可预览同步：按部门、员工分别列出新增、变更及停用，勾选已审阅后才能执行。执行失败后废弃旧预览；目录变化或并发更新要求重新预览。同步结果会刷新员工、部门、候选账号及日志缓存。
- 员工分页支持姓名或钉钉用户 ID 搜索。绑定时显式搜索本地账号姓名、邮箱或完整账号 ID，搜索至少 2 个字符、最多返回 20 个有效候选。候选排除系统账号、停用或删除账号及已经在当前企业绑定的账号；其他企业的绑定不影响候选。直接调用绑定接口也拒绝系统账号。
- 绑定和解绑均有确认对话框，提交员工页面当前展示的 expectedUserId。修改后刷新目录查询缓存。绑定保持只关联身份的边界，不修改本地业务权限。
- 部门页支持逐层浏览、路径返回及按名称搜索；同步日志显示最近 50 次执行状态、起止时间、数量和错误码。

新增的管理员读取接口：`GET /api/admin/organization/dingtalk/listDepartments?corpId=...` 和 `GET /api/admin/organization/dingtalk/searchAccounts?corpId=...&search=...`。管理员读取部门不需要把自身绑定到企业，接口不会放宽普通用户组织查询的成员范围检查。

本页尚未在真实企业凭据下联调；部署前仍需应用目录数据库迁移、配置企业内部应用并授予完整的读取范围。

## 业务角色及映射

新增 `DirectoryBusinessRole` 模型及 `20261109010000_add_directory_business_roles` 迁移。部署时在组织目录迁移之后应用本迁移并生成 Prisma Client。本模型属于组织身份层，未向 v2 Table 领域添加组织概念。

管理员页面的“业务角色”页签支持新建、编辑、启用和停用角色，以及查看匹配成员。角色名称在同一企业内按 NFKC 规范化并忽略大小写唯一，角色保留独立的本地 ID；该 ID 将成为后续矩阵的授权主体。停用保留规则和 ID，便于撤销未来关联的授权并审阅历史配置；当前没有物理删除入口。

规则为以下两类，最多 100 条、同类同主体不能重复：

- 部门映射：使用当前企业的本地部门 ID，默认仅直接成员，可显式包含全部下级部门。
- 钉钉来源角色映射：使用精确的来源角色 ID，匹配本企业同步员工的 externalRoleIds。来源角色 ID 目前没有名称目录；管理员需核对钉钉角色 ID，并通过匹配成员预览验证。没有现有成员的来源角色规则允许保存，其匹配人数为零。

单个角色内按“任一规则匹配”合并，同一员工匹配多条规则只计一次；员工可以同时属于多个业务角色。角色没有隐含的 owner/editor 权限，也不直接转写 Collaborator。未配置规则的角色不匹配任何成员。

实时解析仅接纳在职、已绑定、非系统且本地账号有效的成员，连接和业务角色也必须启用。多部门成员可匹配任一所属部门；下级包含关系只由显式规则决定。停用或移除的部门不再匹配；未解绑而停用的员工仍保留身份记录，但不再获得角色归属。绑定、同步完成和角色编辑后，管理页面刷新匹配成员缓存；服务端解析不使用跨请求的身份缓存。

新增管理员接口（均要求 instance|update）：

| 方法 | 路径                                                                 | 行为                                                                           |
| ---- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| GET  | `/api/admin/organization/dingtalk/listRoles?corpId=...`              | 当前企业的角色和规则                                                           |
| POST | `/api/admin/organization/dingtalk/saveRole`                          | 保存角色；body 包含 corpId、可选 roleId、expectedVersion、name、enabled、rules |
| GET  | `/api/admin/organization/dingtalk/roleMembers?corpId=...&roleId=...` | 有效绑定账号预览，支持 skip/take，take 最大 100                                |

新建角色 expectedVersion 必须为 0；编辑须提供读取时的版本，每次成功编辑递增。企业锁与同步、绑定共用，竞争或旧版本更新返回 409，不覆盖配置。启用规则中的部门必须属于当前企业且有效；停用角色不强制验证历史部门，以便禁用已失效的规则。保存成功向现有审计管道发出角色变更事件。

`DirectoryRoleService.resolveForUser` 提供后续矩阵使用的实时身份解析入口。当前只完成角色归属和预览，尚未接入资源访问判定。矩阵接入时应使用实时角色 ID，将业务角色权限与现有手工协作者授权分别计算；本阶段没有自动撤销手工授权、全局禁用本地账号或授予表权限。

## 后台配置企业连接（第 10 期）

`/admin/directory` 提供“配置钉钉企业”入口，支持新增、编辑数据库连接及只读测试凭证和根部门读取能力。AppSecret 强制加密保存，不向页面返回；编辑留空保留，更换 AppKey 必须提供新密钥，CorpId 保持不可编辑。配置版本参与同步预览 token 和提交检查，并与同步共用企业锁，防止修改配置后执行旧预览。

新增迁移 `20261109030000_add_directory_credentials`，在既有连接行中保存 AppKey、加密 AppSecret 与版本。环境变量连接继续作为只读来源。后台配置只对实例管理员开放，不自动同步、不改变业务授权。完整需求、存储设计、部署和验证记录见知识库第 10 期。

## 权限验证、实时撤销与数据限制（第 11—14 期）

已补真实 HTTP / PostgreSQL / SockJS 验收，使用独立临时空间和账号检查 v1/v2 及权限撤销，不变更真实员工。ShareDB 增加发送边界的文档 op、查询 diff 身份和资源权限复核；失效时停止投递并关闭连接。

矩阵页面新增按本地邮箱和表的权限预览，解释数据库访问资格、匹配角色和协作者/矩阵来源。策略 JSON 新增可选独立 restrictions，支持字段隐藏、只读及按系统创建者限定本人或同企业直接部门成员记录。普通身份同时受到原授权和数据限制；有效实例管理员保留管理入口。支持的数据操作由全局 HTTP 清单和实时发送边界强制执行，未知高能力入口保守拒绝。

该首版尚不支持自定义条件、任意负责人字段、受限身份的 SQL/导出、位置批量写、完整派生字段解释及全部插件通道。具体语义、数据通道影响和验证范围以知识库第 11—14 期为准，不把本地验证视为全通道生产验收。

## 综合回归补强（第 15 期）

复制数据库须独立检查 `fromBaseId` 与目标 `baseId`，目标可写不代表可以复制受限源。限制传播沿有效关联、lookup 和 conditional lookup 的外键引用求闭包，跨数据库和多层引用都参与表级以及数据库级复制/导出检查；派生表使用保守的隐藏规则，不自动继承源表的创建者范围。

ShareDB 的初次 `qs/qf` 回复不携带集合名，须按原请求 ID 查回集合，并在发送前重新鉴权。数据检查同时核对初次查询、插入 diff 和 bulk fetch/subscribe 中的每个记录 ID，避免仅检查顶层 `d`。隐藏字段查询回复同样检查文档 ID；不满足当前范围的整个消息停止投递。

字段名称可能是 `id`、`name`、`type`、`fields` 等结构键。名称及数据库列名的删除仅用于单元格字段映射；其他 DTO 保留自身结构。整体替换字段映射的实时 op 仍分别处理新旧值，并保持共享原操作不变。完整发现、测试结果和剩余限制见知识库第 15 期。

## 可见字段查询与上线准备（第 18 期）

受限账号支持可见字段的个人筛选、排序、分组和搜索。HTTP 边界按结构检查字段引用，搜索显式携带可见字段列表，并与调用者 projection 取交集；即使搜索计数或分组接口丢弃 projection 也不能扩大范围。查询仍 AND 当前创建者范围，忽略共享视图条件并去掉未校验 queryId。记录位置入口先核对记录归属，其余未审查聚合入口仍拒绝。

表权限增加可选 dataRestrictionsEnabled；页面自动保持个人视图，用户可以通过工具栏操作排序、分组和搜索，不尝试保存共享视图。v1 91 项、v2 + Chrome 104 项真实验收、216 项相关单测及前后端完整类型检查通过，生产镜像、TLS、真实恢复演练与容量压测仍待目标服务器完成。

单机 Compose、环境生成器、nginx 示例、一致性备份脚本及恢复/验收流程位于 `deploy/organization-community`。搬迁现有数据库必须同时保留加密根密钥、旧密钥回退和附件；新建实例随机密钥不得覆盖已有密文对应配置。完整需求与证据见知识库第 18 期。
