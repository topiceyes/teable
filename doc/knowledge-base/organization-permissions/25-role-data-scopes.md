# 第 25 期：按角色配置字段和记录范围

日期：2026-11-11。目标版本：1.3.0。

## 需求

按既定顺序，在人员授权总览与诊断之后，让同一张表可以表达员工看本人、负责人看直接部门、管理人员看全部，并针对角色分别配置隐藏字段和只读字段。保留现有按表默认限制及原有追加授权语义。

## 规则与设计

- 每张受限表保留原有默认范围，新增有序 `roleOverrides`，每项为 roleId、rowScope、hiddenFieldIds、readOnlyFieldIds。未配置角色范围的旧策略行为保持一致。
- 从上到下选择第一个命中的有效业务角色，整组替换默认的记录范围、隐藏和只读字段；不把多个角色的字段或记录范围拼接。管理员可上移、下移；同表不允许角色重复。
- 没有角色命中时使用默认范围。新增角色项复制当前默认值，管理员再显式修改。默认范围可设本人以便失去角色时收窄，但不会自动重写任何既有策略。
- 角色范围不授予数据库成员资格或表级读写。既有成员/表权限仍先校验，再叠加所选范围。实例管理员保留既有字段和记录管理豁免。
- 角色必须是策略所属企业中的启用业务角色，所有引用的表和字段必须有效且属于该库/表；默认或任一角色选择本人/部门时，表必须有创建人字段；任何范围都不能隐藏主字段。
- 每张表最多 100 个角色范围，策略仍最多 1000 张受限表。角色/字段重复及未知字段由严格契约拒绝。停用策略仍允许带失效引用保存，方便紧急停用。
- 实时解析目标账号的有效角色，不缓存其业务角色授权。只匹配相同企业；员工停用、解绑、角色或连接停用后落回默认范围。默认范围本身不保证全部本地授权撤销，其行为在页面明确说明。
- 跨表关联、派生值、复制/导出等受限通道沿用现有保守处理，即使命中 all 范围也不自动开放未审查通道。角色“全部记录”仅调整该表的记录/字段范围。
- `scope(tableId, userId)` 将显式目标 userId 传递给角色范围解析；人员诊断和发送前实时过滤不能使用检查管理员身份。权限预览和人员总览显示命中的角色，未命中显示默认范围。

这是现有 Nest/OpenAPI 应用层的授权配置；不改 v2 Table 领域。存储沿用 JSON，无数据库迁移。策略 version=1 保持兼容新后端读取旧策略，但旧后端的严格解析不认识 `roleOverrides`；回退旧应用前必须检查并处理已保存的新策略，不能直接宣称无条件回退兼容。

## 界面

权限矩阵 → 字段与记录限制：每张表先编辑默认范围，再添加角色范围。角色项可分别选择全部/本人/直接部门、隐藏和只读字段。角色顺序即匹配顺序，调整后必须重新审阅并保存。更换企业依旧提示并清空相关配置。权限预览与员工“查看权限”标明数据范围来源。
