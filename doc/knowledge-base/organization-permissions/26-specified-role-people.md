# 第 26 期：指定人员加入业务角色

日期：2026-11-11。目标版本：1.3.1。

## 需求与入口

修补业务角色只能按部门或钉钉来源角色配置的缺口，支持直接指定员工。入口：后台 → 组织与钉钉 → 业务角色 → 新建/编辑角色 → 指定人员。按姓名或钉钉员工 ID 搜索，可留空浏览、分页、添加和移除，保存角色后生效。

## 设计与规则

- 角色规则新增严格结构 `{type:'member',memberId}`；使用当前企业目录员工的稳定 ID。部门、来源角色与指定人员为 OR 关系；重复命中不增加权限。
- 保存启用角色时校验所有指定员工属于当前企业且未离职；不允许跨企业或任意本地账号 ID 绕过身份绑定。可以预配置未绑定员工，只有绑定有效本地账号后才有生效角色。
- 查询与实时解析共同传入目标员工 memberId，保留有效企业、有效员工、有效非系统本地账号及启用角色过滤。解绑、离职、账号停用或连接/角色停用后授权实时失效。指定人员规则不自动创建数据库成员资格，也不自行授予表操作权限。
- 页面显示员工姓名、钉钉员工 ID、部门及绑定状态，已选人员用精确 ID 批量回查，与搜索分页独立；已选或离职人员不能重复添加。原有 listMembers 接口增加可选 memberIds 过滤（最多 100 个），查询和计数均限定当前企业。
- 指定人员与原有规则共用每角色最多 100 条限制。保留管理员鉴权、审计、企业同步锁、角色 expectedVersion 并发校验及重名校验。保存失败保留编辑内容。
- 移除指定人员只移除直接规则；如果仍命中部门或来源角色，角色继续生效。页面明确提示这一点。
- 人员诊断、权限矩阵与字段/记录角色范围沿用同一实时角色解析，无需另设授权来源。

## 兼容性与回退

无数据库迁移，新增规则保存在既有 JSON 中。新后端兼容旧规则；旧后端严格 schema 不认识 member 规则，回退应用前必须在当前版本检查并处理该类新规则，不能把已保存的人员规则原样交给旧后端。字段范围 roleOverrides 的上一期回退限制仍适用。
