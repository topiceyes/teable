# 第 17 期：部门权限试点验收

日期：2026-11-10。

## 需求与结果

用户要求代为执行部门权限试点。采用三个临时员工账号、父子两个临时部门、一个临时空间及数据库，验证角色授权、字段只读、记录隔离，以及解绑、离职等状态变化后的撤权。真实钉钉组织目录保持不变。

结果：v1 真实验收 60 项通过；v2 的同一套场景加 Chrome 页面检查共 66 项通过。两次进程均退出 0，清理断言均确认临时空间、账号、企业连接数量为 0。本轮没有发现需要修改业务实现的问题。

## 夹具和设计

| 身份       | 目录所属       | 原始数据库权限 | 试点授权与范围                                                       |
| ---------- | -------------- | -------------- | -------------------------------------------------------------------- |
| A          | 父部门         | viewer         | 业务角色追加记录读写；可见本人及同一直接部门 B 的记录                |
| B          | 父部门         | viewer         | 与 A 对称；后续临时改为 editor 验证手工授权保留                      |
| C          | 子部门         | viewer         | 首先不匹配父部门直接规则；显式包含下级后获得读写，但仍只看子部门记录 |
| 实例管理员 | 不加入试点部门 | 原有管理身份   | 创建外部创建者记录，验证普通员工不能读取该记录及敏感值               |

表含 Name、Sensitive、Locked、Creator 四个字段。Sensitive 隐藏，Locked 只读；记录范围先使用 department，随后切换到 own 并切回，确认已有会话按当前策略执行。

试点区分两种规则：角色规则可以显式包含下级部门；department 记录范围仍按共同的直接部门定义。角色匹配 C 不代表 A 能读取 C 创建的记录。

## 实施方式与数据边界

新增可复用脚本：`apps/nestjs-backend/scripts/verify-department-permissions.cjs`。

脚本固定本机 `http://localhost:3000` 和开发库 `teable_dev_20261109`，从 stdin 读取管理员密码，不打印或保存密码及会话。账号和目录夹具带随机 ID，测试密码随机生成；只给这些账号和夹具写入状态。

- 基础夹具通过参数化 SQL 建立临时账号、企业、部门、员工及协作者关系；这些数据不调用真实钉钉。
- 员工绑定/解绑、角色新增/编辑/停用、矩阵保存和业务读写使用实际管理员或员工 HTTP 会话。
- 离职状态模拟同步完成后将指定临时员工设为 inactive；企业连接停用及本地账号停用也只修改对应夹具行。没有测试真实钉钉远端发出离职变化及同步全过程。
- 每轮结束删除临时空间、目录连接和账号，并在数据库中再次验证实际目标 ID 均不存在。清理失败会令验收进程失败。

## 已通过场景

| 范围           | 实际验证                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 绑定与管理边界 | 三账号通过管理员 API 绑定；旧 expectedUserId 返回 409；普通员工不能更改绑定；父子部门树正确                                                |
| 角色授权       | 只有绑定没有矩阵时不能新增；直接部门角色匹配 A/B；显式包含下级后匹配 A/B/C；创建记录响应确认各自执行请求的 v1/v2 引擎                      |
| 部门记录隔离   | A/B 对称读取两条同部门记录；C 只读取自己一条；管理员创建的外部记录不进入员工范围；同部门可更新，跨部门更新拒绝                             |
| 字段约束       | 列表不返回隐藏字段；隐藏和只读字段写入拒绝；返回的单元格权限将 Locked 标记为不可更新                                                       |
| 范围旁路       | 计数为可见的两条；混合本部门和子部门 ID 的快照请求拒绝；切换 own 后不重新登录即只剩本人记录                                                |
| 解绑与恢复     | 管理员解绑后旧会话的部门列表为空、追加写权限消失；重新绑定后恢复当前范围                                                                   |
| 离职与已有连接 | B 离职后 A 看不到 B 的记录，B 旧会话无部门数据、不能写入；inactive 员工不能重新绑定；A 已打开的 B 记录订阅在后续更新时关闭，未收到离职后值 |
| 手工权限       | 角色停用后 A 写入被拒绝；独立 editor 授权仍允许 B 更新范围内记录，仍不能越过部门记录限制                                                   |
| 企业及账号状态 | 企业连接禁用后部门范围为空、矩阵追加写权限消失；B 本地账号停用后其记录从 A 范围移除，B 旧 HTTP 会话被拒绝                                  |
| 管理员预览     | 最终预览返回实际业务角色及 department 范围，与请求行为一致                                                                                 |
| Chrome         | A 实际页面有两条记录，C 有一条；WebSocket 快照只含允许记录，无其他部门/管理员记录及敏感值；两页面无 pageerror 或 Runtime Error 浮层        |
