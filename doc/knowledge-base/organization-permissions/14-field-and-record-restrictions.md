# 第 14 期：字段与记录访问限制

日期：2026-11-10。

## 需求与授权语义

在第 07 期“角色追加表操作权限”之外，提供独立、明确启用的数据限制。保持原有授权规则及数据库成员资格检查，然后对普通身份叠加字段和记录范围。实例管理员保留管理访问；该例外以数据库中当前有效的管理员身份判断。

现有 `TableAuthorityPolicy.policy` JSON 增加可选 `restrictions`，旧策略无需迁移。每个表最多一条限制：`tableId`、`hiddenFieldIds`、`readOnlyFieldIds`、`rowScope`。记录范围为 all、own、department。隐藏和只读不会自动授予读取或写入权；停用策略则停止其追加授权和数据限制。

页面增加“字段与记录限制”编辑器；任何更改仍须重新审阅后保存。字段候选由原管理员 options 接口返回，保存校验表和字段归属。主字段不能显式隐藏；本人/部门模式要求表有创建人字段，避免过滤机制失效。

## 记录范围

- own：记录系统创建者为当前账号。
- department：当前账号须绑定当前企业的有效员工；可见记录的创建者须同样绑定有效本地账号，且与当前员工有至少一个共同的直接部门。只检查本企业，不默认包含下级部门。
- 解绑、员工停用、账号停用或企业连接停用会改变后续部门范围。没有有效部门身份时范围为空，不能回退到全表。
- 记录列表和 socket doc-id 查询在 Nest 管道执行之前，将服务端创建者条件与客户端 filter 用 AND 合并；客户端的 OR 和 ignoreViewQuery 不能替代范围。记录计数也使用同一条件。
- 单条读取、快照恢复、更新和删除按真实数据数据库的 `__created_by` 验证全部目标 ID；使用 DatabaseRouter 路由和参数绑定。批量内有任意范围外目标时整个请求在处理器之前拒绝。

当前范围按创建者定义，不是任意“负责人”字段或自定义条件规则。

## 字段与派生值

请求侧按字段 ID、名称或数据库字段名校验写入，隐藏或只读字段拒绝；读取时强制可读投影并递归剔除受限字段和元数据。记录权限 DTO 使用已有 read/update 映射，使网格及展开编辑器锁定只读单元格；字段 recordCreate 标志也同步限制。

为避免隐藏值从计算或关联中复制泄露，当前保守隐藏受限表的计算、查找和关联字段（保留创建人等身份字段）；其他表引用受限表的 link 及相关派生字段同样隐藏。不会对共享 pub/sub op 原对象做修改。字段 op 从单连接消息中剔除，同时保留文档版本推进；范围外文档或不适合安全修改的元数据 op 关闭连接，要求重新读取。

## 明确的首版限制

- 不支持在受限身份下执行位置粘贴、upsert、历史、导出、SQL、附件数据通道、自动化、复杂查询、关联写入或未审查的数据入口。这些请求拒绝执行，不以隐藏页面按钮替代校验。没有可解析资源范围的高能力数据通道，在已有数据限制时采取保守拒绝，可能影响该普通账号的其他相关操作。
- 受限读取只使用显式请求筛选，忽略视图保存的筛选/排序，防止隐藏字段谓词成为旁路；搜索、分组及排序入口尚未提供细粒度支持。
- presence 富事件及受限元数据变更需要重新加载，不保证所有实时 UI 功能保持无缝。
- 本期是已有 HTTP/ShareDB 社区应用边界的实现，不改 v2 领域接口；不代表全部内部任务、生产 BYODB、第三方插件和外部数据库访问通道均完成审计。
- 已下载的数据、已取得的独立公开资源和已执行事务不能被追溯收回。启用生产限制前应在目标使用流程中验收。

## 实现入口

- `table-data-access.service.ts`：限制解析、当前部门成员、参数化记录检查、查询约束、返回值及实时消息处理。
- `table-data-access.interceptor.ts`：全局 HTTP 入口的支持清单、请求前拒绝和响应投影，位于全局认证/资源授权之后。
- `MatrixDataRestrictions.tsx`：限制配置；`MatrixPermissionPreview.tsx`：最终权限与范围说明。
- `share-db/document-authorization.ts`：发送前资源校验和数据处理回调。

## 验证和部署

截至本期组合验证：组织目录、矩阵、权限 Guard、关联标题插件和实时回归共 21 个文件、220 项通过；前端矩阵与目录共 2 个文件、19 项通过。覆盖隐藏字段谓词、字段 ID/名称写入、范围合并、部门解绑、批量混入范围外 ID、socket 快照、未知入口拒绝和客户端配置审阅。

最终 v1 通过 47 项真实 HTTP/数据库/WebSocket 验收；v2 在相同基础上加上 Chrome 管理页、受限表验证，共 54 项通过。浏览器确认管理员预览和限制编辑器可用，普通账号收到并显示本人记录快照，敏感数据没有进入实时消息帧，没有页面 JavaScript 错误或开发运行时浮层。单元测试与真实验收分开统计，不把重复执行累计为新增用例。

没有给真实企业保存数据限制，也没有批量改动真实员工绑定、业务角色或协作者权限。当前用户可以先在测试数据库页面配置并验证。新增内容使用已有 JSON 存储，无数据库迁移；已部署到本地开发服务。真实企业目录保持 196 个部门和 334 名员工；最终只读检查确认临时空间、账号和企业连接均已清理，健康检查正常。

## 浏览器兼容修复

真实浏览器验收发现被拒绝的可选 presence 订阅会通过 EventEmitter 或开发日志产生错误浮层。服务端在受限数据库/表的权限 DTO 返回 `realtimeEnabled=false`，SDK 的共享 presence 连接入口据此停止打开可选通道；服务端鉴权仍保留。SDK 同时给 presence 安装独立错误监听器，避免其他订阅调用没有 callback 时产生未捕获异常。相关 SDK 测试 3 个文件、15 项通过。

网格默认发送空排序/分组列表不代表复杂查询，已允许该空参数组合；非空未支持查询仍拒绝。浏览器截图确认隐藏字段不出现，网格显示本人记录及正确计数。已执行修改文件 lint、格式和 git diff 检查；前端完整类型检查通过，后端仍有此前 363 行其他文件类型错误，本期文件没有报错。

记录目标检查发生在 HTTP 处理器之前。当前没有把目录变更、策略变更与完整 v1/v2 写事务统一为一个事务性授权快照；不能承诺并发撤销会中断已经通过检查的请求。内部任务不经过该 HTTP 拦截器时，也须另行审查；本期没有宣称任意后台插件都获得同等策略执行保证。
