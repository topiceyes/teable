# 第 12 期：实时文档推送撤销

日期：2026-11-10。

## 需求与发现

第 08 期只覆盖 presence。已订阅的 ShareDB 文档操作和查询差异还须在发送前检查当前身份和资源权限，不能沿用建立 socket 时的判断。

检查当前安装的 ShareDB 5.2.2：文档 op 和查询 diff 最终调用 `Agent.send`，普通 reply 中间件并不覆盖全部异步推送。新增 `share-db/document-authorization.ts`，在连接中包装这个发送边界，而非只检查新订阅。

## 实现

- 每次文档或查询差异发送前，重新读取服务端确认的 session、有效本地账号以及实际表/数据库读取权限。
- 表、字段、视图和记录 collection 分别解析到表或数据库资源；未知数据 collection 拒绝投递。
- 查询 ID 与 collection 在该连接内关联，异步 diff 即使没有 c 字段也可授权；退订与一次性查询完成后清理，限制关联数量。
- 通过单连接异步队列保持消息与文档版本顺序。权限检查失败或存储故障时，在数据进入流之前关闭连接；服务端可信内部连接保持原路径。
- 分享每次调用原有有效分享校验，模板沿用资源检查，不把客户端模板 header 当作可信授权。
- 预留服务端数据脱敏回调，第 14 期用它检查行范围并隐藏 op 中的受限字段。presence 中的富事件无法逐字段审查时，受限身份拒绝该数据通道。权限 DTO 的 realtimeEnabled 标记让 SDK 在打开页面时停用这些可选订阅；服务器仍对后续每次请求和投递检查。

不回收客户端已收到的数据，不主动终止已开始的事务；空闲连接没有数据发送时不会因这个钩子立刻关闭。普通页面收到关闭后可重连，新连接仍须通过当前权限检查。

## 验证

新增 `document-authorization.spec.ts`，使用实际安装的 ShareDB client/server 与 MemoryDB，覆盖正常顺序投递、撤销读取、账号停用、session 失效和数据范围检查故障时拒绝发送，共 5 项。连同既有 presence、query cancellation 和错误传输测试，首轮 4 个文件 59 项通过。

第 11 期脚本还通过应用实际使用的 SockJS WebSocket 传输订阅记录，移除临时账号数据库成员资格后由管理员写入新值，验证 socket 关闭且消息帧中不含新值。v1 和 v2 两条路径均通过。

本期不新增迁移；完整组合回归结果见第 14 期。未做生产连接规模吞吐测试，发送前存储检查会增加读取开销。
