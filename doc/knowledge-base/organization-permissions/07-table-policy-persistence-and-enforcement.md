# 第 07 期：表级追加权限的配置、存储与请求校验

日期：2026-11-09。

## 需求与范围

将第 06 期独立策略计算器接入后端，提供可保存的权限配置和社区版页面。第一版按业务角色给指定表追加记录读写权限，不能撤销独立手工授权，不能创建数据库成员资格，不是企业版完整字段/记录权限替代。

## 设计

- 一个数据库一份策略，绑定一个目录企业，规则引用该企业的业务角色及本数据库内的表。
- 保存、读取及候选项接口均要求实例管理员和 `instance|update`，不放宽普通数据库创建者到任意企业的读取资格。后续可另行设计企业管理员与数据库管理员的委派边界。
- 首次 revision=0，保存后为 1；编辑比较 revision 并递增。数据库 advisory lock 防止同数据库并发写。停用历史策略时不强制验证已消失的引用。
- 启用时校验有效数据库和空间、启用的企业和角色、当前数据库的非删除表。存储外键约束数据库及企业，revision 必须为正数。
- 对普通用户的表级资源权限，先取得既有数据库/空间授权，再根据目录实时身份追加表规则。无数据库访问资格时直接拒绝，不使用矩阵兜底。
- Access token 最终仍与自身 scope 和资源范围取交集。分享、模板、内部临时令牌、机器人及匿名身份不追加权限；回收站操作不使用本期矩阵。
- 表权限 DTO 通过同一请求权限服务计算，避免仅开启界面按钮或仅开放后端。矩阵支持读、增、改、删记录，不支持字段结构管理、表结构、导出或邀请。

## 实现入口

- 契约与共享校验：`packages/openapi/src/organization/table-authority-policy.ts`，通过原有 OpenAPI 注册机制输出。组织权限属于现有 Nest/OpenAPI 应用层，未新增 v2 Table 领域接口。
- 存储：`TableAuthorityPolicy`，迁移 `20261109020000_add_table_authority_policy`。
- 服务和配置入口：`apps/nestjs-backend/src/features/organization/authority-matrix/table-authority.*`。
- 请求权限入口：`PermissionService.getPermissionByTableId`；先验证表归属并取得数据库权限，再调用追加权限服务。
- 前端 DTO：`TableOpenApiService.getPermission`，返回有效操作映射。
- 页面：`AuthorityMatrix.tsx`，替换社区版原升级提示。现有数据库的权限矩阵入口保持原地址。

## 管理接口

| 方法 | 地址 | 行为 |
| --- | --- | --- |
| GET | `/api/authorityMatrix/get?baseId=...` | 读取策略；无配置时返回停用状态和 revision=0 |
| GET | `/api/authorityMatrix/options?baseId=...` | 实例管理员可选的有效企业、业务角色和本数据库数据表 |
| POST | `/api/authorityMatrix/save` | 保存 connectionId、expectedRevision、policy；保存即对后续请求生效 |

页面需选择企业及角色/表，添加规则并勾选写操作；每次修改都取消已审阅标记。用户确认配置后才能保存。版本冲突保留本地编辑并提示重新加载；更换企业会清空未保存的规则。

## 验证与限制

本期实际验证结果：

- 组织、矩阵、原权限服务及权限 Guard：15 个测试文件、126 项通过（内存缓存环境）。
- 表服务及表控制器回归：2 个测试文件、29 项通过。首次与大批测试并行时控制器动态加载钩子超时，单独重跑并使用内存缓存和 30 秒钩子上限后通过。
- 前端矩阵与目录管理交互：2 个测试文件、13 项通过。
- PGlite 按序应用三份目录/矩阵迁移，验证数据库及企业外键、正 revision、比较更新和级联清理通过。
- 前端全量类型检查通过；后端全量类型检查仍存在其他已有文件报错（输出 363 行），未指向本次矩阵、权限接入及表权限 DTO 文件。
- Prisma schema 校验、修改文件 oxlint、oxfmt 和 git diff --check 通过。

以上不替代实际部署联调。

新增策略、角色和目录迁移需按序部署并生成 Prisma Client，尚未应用到实际数据库。真实钉钉和浏览器生产环境尚未联调。

本期只对以 tableId 调用 PermissionService 的请求路径追加权限。数据库级 SQL/导出、需要额外目标表权限的跨表写入、实时订阅及其他单独权限插件仍保留自己的授权限制，不能据此声称所有入口都完整支持矩阵授权。配置更新不主动向所有在线客户端广播权限变化；服务端下一次请求使用实时身份，前端可刷新或重新进入表更新权限显示。后续需单独验证完整 v1/v2 写入、批量、链接副作用、订阅及撤销用例。
