# 第 24 期：人员授权总览与权限诊断

日期：2026-11-11。目标版本：1.2.0。

## 需求与交互

用户同意按“人员总览＋诊断 → 角色级数据范围 → 变更影响与历史”的顺序完善。本期交付第一项，解决需要跨员工绑定、业务角色、数据库成员和矩阵页面逐一排查的问题。

在组织目录及矩阵内嵌员工列表增加“查看权限”。管理员选择员工后，在只读弹窗集中查看当前本地账号状态、直接部门、所属企业有效业务角色，以及各数据库的访问资格、本地成员授权来源和矩阵状态。展开数据库查看数据表的进入、读取、新增、修改、删除权限、授权来源、隐藏/只读字段及记录范围。支持数据库/空间搜索、表名搜索、独立分页和重新检查，并提供矩阵新标签页入口。

为诊断“为什么看不到”，数据库列表包含当前实例的有效数据库，包括员工没有成员资格的库；仅实例管理员可查看。默认每页 10 个，最大 20 个，只计算当前页；表明细按需加载，也按页计算，不一次扫描全部表或全部员工。没有业务记录读取、写入或自动授权。

## 接口与设计

- `GET /api/authorityMatrix/memberOverview`：corpId、memberId、search、skip、take。核对员工确属指定钉钉企业后，返回身份、有效角色及数据库页。
- `GET /api/authorityMatrix/memberTables`：附加 baseId。只允许有效数据库及有效空间，返回当前表页的实际权限与诊断。
- 两接口沿用矩阵控制器的 `instance|update`，参数严格校验、分页上限与搜索长度限制。普通账号不能调用，即使传入他人 ID 或其他企业标识。
- 复用现有 `TableAuthorityPreviewService`、`PermissionService`、`DirectoryRoleService` 与 `TableDataAccessService`。权限计算在新的目标员工 CLS store 中运行，不继承管理员、PAT、分享、模板或祖先缓存。新诊断不给目标账号创建登录会话。
- 只有明确的无资源权限异常可转换为“没有库访问资格”；基础设施及未知错误返回失败，界面说明“计算失败不代表没有权限”，不默认为拒绝。
- 数据库/空间本地成员来源按该账号的用户协作者记录显示。有效业务角色和矩阵表授权单独展示。角色匹配不替代数据库成员资格。
- 员工停用、解绑或企业停用不被描述为撤销全部本地权限：业务角色与部门范围按实时状态计算，独立的本地协作者权限仍按实际结果展示。停用矩阵会同时停止追加权限及该矩阵的数据限制。
- 记录范围按创建者定义；部门范围为空明确说明，不回退全表。仅返回字段展示名称与范围类型/空范围标志，不返回数据库表名、数据库字段名或完整创建者 ID 集合。
- 响应含检查时间；这是当前交互账号的只读计算，不是权限与后续写事务的原子快照，也不覆盖访问令牌、分享链接、后台任务。管理员字段和记录范围豁免单独解释。

框架无关契约位于现有 `packages/openapi/src/organization/member-authority.ts`。本期不改 v2 Table 领域，不新增数据库迁移，不调整任何真实员工、业务角色、协作者或生产矩阵。

## 测试与上线

- 后端组织目录、矩阵和钉钉登录回归：193 项通过，5 项需显式启用的既有钉钉数据库测试跳过；新增诊断及身份隔离用例包含在通过项中。另行矩阵服务/集成组合为 37 项通过，不累计重复用例。
- 前端诊断、目录、矩阵和钉钉入口：36 项通过。
- 前后端完整类型检查通过；本期代码格式、lint 检查通过。
- 本地真实 HTTP/Chrome/数据库验收 42 项通过：普通账号拒绝、跨企业员工拒绝、分页上限、未绑定账号、角色与库成员资格分离、字段和部门范围、浏览器入口和重新检查、角色撤销、独立成员编辑权保留、离职及连接停用诊断、账号停用、策略停用/异常和删除库排除。合成数据清理成功，未修改真实员工。
- 首次浏览器夹具未包含后台企业连接列表要求的模拟 appKey/appSecret，企业未展示，导致等待超时；当次已清理，补齐合成凭据后完整重跑通过。没有调用真实钉钉授权或同步接口。

真人钉钉扫码不属于本期验收。部署回执保存在本地私有知识库。
