# 第 11 期：权限矩阵真实端到端验收

日期：2026-11-10。

## 需求与设计

先跳过真实员工批量绑定和业务角色配置，在隔离夹具中验证已有表级追加权限。不得把实例管理员成功访问当作普通账号授权正确，也不修改真实钉钉目录来制造测试数据。

新增 `apps/nestjs-backend/scripts/verify-community-permissions.cjs`。它对正在运行的本地 HTTP 服务创建独立临时空间、数据库、测试表、普通账号和测试企业目录，通过管理员 API 保存矩阵，再用普通账号执行记录增改删和粘贴扩行。夹具通过直接数据库操作模拟角色停用、员工离职、解绑及移除数据库成员资格，随后再次使用 HTTP 验证拒绝结果。恢复手工 editor 授权后验证派生角色撤销不影响独立授权。

脚本仅允许本机 PostgreSQL，固定目标为 `teable_dev_20261109`；管理员密码从 stdin 读取，测试账号使用随机密码。不输出 cookie、密码和数据库凭证。测试结束退出会话并清理测试空间、目录和账号，保留失败退出码。真实企业和员工不参与夹具。

## 覆盖范围

- viewer 无矩阵时不能创建；获得矩阵授权后可以创建、更新、删除及粘贴扩行。
- 记录授权不扩大到字段结构管理，也不赋予另一目标表的创建权。
- 使用关联标题写入后，独立读取目标表验证没有未授权插入。当前实际路径对未解析标题返回 200、目标仍为空，不把这个结果写成“服务器返回 403”。
- 角色停用、员工离职、解绑后派生写权限失效；没有数据库成员资格时，矩阵不能提供入口资格。
- 原有手工 editor 权限得到保留。
- 后续第 12—14 期扩展同一脚本，加入真实 WebSocket、权限预览、字段和记录范围的验收。

## v1 / v2 与实际验证

`TEABLE_ACCEPTANCE_MODE=v1|v2` 控制夹具数据库标记和 `x-teable-canary`，并检查实际记录写响应的 `x-teable-v2` 头，避免仅声称覆盖两个版本。

两种模式均已完成包含实际 WebSocket 的 46 项验证。新增记录计数及浏览器验收后，最终数量与结果以第 14 期记录为准，不将同一用例多次重跑累计为不同覆盖项。

这属于本地真实 HTTP、数据库与 socket 验证，不等于生产环境、BYODB 或全部第三方集成验收。没有修改 v2 核心模型或命令。
