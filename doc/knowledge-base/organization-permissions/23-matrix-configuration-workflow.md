# 第 23 期：权限矩阵配置流程完善

日期：2026-11-10。目标版本：1.1.1。

## 需求

用户在真实试用中反馈“配置权限、角色或成员时不顺手”。本期完善管理员从选择企业、建立业务角色、绑定员工账号、准备数据库成员，到编辑和保存矩阵的操作流程。

## 设计与实现

- 矩阵页按企业、成员准备、授权规则、字段/记录限制、保存与权限预览排列。只有一个可用企业且没有历史策略时自动选择企业；有历史配置时不替换所属企业。
- 在矩阵页内展开业务角色和员工绑定管理，复用组织目录的既有组件、接口、身份鉴权、版本检查和审计逻辑。角色保存后刷新候选项，保留尚未保存的矩阵编辑。明确提示角色与绑定修改独立生效。
- 数据库成员入口打开当前数据库的既有分享/成员管理。说明账号绑定、业务角色和数据库成员的不同用途，建议先用只读成员配合矩阵追加写权限。没有自动创建协作者或提升任何真实用户权限。
- 业务角色的部门选择增加名称/完整路径搜索；员工绑定预填邮箱或姓名作为搜索词，仍需主动搜索、选择具体账号并确认，不能凭邮箱自动绑定。
- 添加“只读”“新增与修改”“新增、修改与删除”快捷配置，支持为一个角色补充全部现有表的规则。已有规则保留，重复项跳过；后续新建表不自动授权；总规则上限仍为 1000。
- 更换企业且存在规则/限制时，先确认再清空编辑；重新加载有更改的策略时先确认放弃编辑。浏览器关闭/刷新有更改的页面时使用离开提示。不会把后台刷新得到的策略替换到尚未保存的编辑中。
- 保存展示版本及规则/受限表数量，保存成功使用服务器返回值更新编辑基线。区分版本冲突、引用已不可用及一般错误，失败保留编辑；重新加载失败同样保留编辑。
- 无企业、无角色、无表、策略停用、缺少创建人字段均提供具体下一步提示。候选项可单独刷新；权限预览明确说明未保存更改不参与计算。

管理员专用 `/api/authorityMatrix/options` 增加连接的 `corpId`，用于在正确企业下管理角色和员工。接口仍要求 `instance|update`，查询只选择企业标识、名称及业务角色，不返回应用凭据。本期无数据库迁移，不改 v2 Table 领域，也不修改权限计算或普通员工的数据访问边界。

## 验收

- 前端矩阵、组织目录、钉钉入口共 31 项测试通过；覆盖同页创建角色及绑定、批量配置保留旧规则、切换企业确认、重载失败、后台刷新与版本冲突保留编辑。
- 后端矩阵服务与请求权限集成共 21 项通过；管理员候选响应、普通用户拒绝、原有角色/表范围及 PAT 交集逻辑均保留。
- 前后端完整类型检查通过；本期文件格式和 lint 检查单独记录。
- 本地真实 Chrome/HTTP/数据库配置流程 24 项通过：合成企业下搜索部门、新建角色、批量配两张表、选择并绑定合成账号、角色实际成员核验、打开当前库成员管理、保存后读回版本和规则，以及取消重载保留修改。
- 浏览器测试中的临时空间、企业、部门、角色、账号与会话均清理；未修改真实员工或业务权限。未以本期验收替代真人钉钉扫码测试。

## 边界

仍沿用现有追加授权语义和本人/直接部门创建者范围。受限账号的导出、SQL、自动化等未支持通道保持原限制。本期验证成员管理入口正常打开；完整新增/调整成员权限仍使用既有成员管理流程。
