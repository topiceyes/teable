# 第 08 期：批量、跨表权限验证与实时 presence 撤销

日期：2026-11-09。

## 需求与验收目标

验证第 07 期的追加矩阵权限不会因批量或跨表操作扩大范围；确认实时连接能感知授权撤销，并把实际发现和未验证部分分别记录。

## 检查发现

HTTP 记录和选区操作通过权限 Guard 或 PermissionService 校验实际目标；upsert 的混合模式要求 record|create 与 record|update。链接标题新增记录的既有插件单独校验目标表的创建权限和 PAT 上限，反向字段结构变更的既有插件单独校验目标结构权限。矩阵没有字段授权能力，不能借记录授权取得结构管理权。

实时文档快照与查询通过带原 cookie/分享信息的 HTTP 只读适配器请求；本期没有改写这些路径，也没有宣称已验证文档 op 流撤销。

实际发现 presence 中间件存在以下问题：

1. 对每个连接和通道长期缓存首次允许或拒绝结果。
2. 对分享范围长期缓存，关闭分享后可能继续沿用旧范围。
3. 只检查入站消息，没有对已订阅客户端的数据推送重新鉴权。
4. socket 连接时保存用户 ID，此后不重新检查会话及账号状态。
5. 表 presence 只检查数据库授权是否成功，没有明确检查该表的读取权限。

## 实现与边界

修改 `apps/nestjs-backend/src/share-db/auth.middleware.ts`：

- 去除连接生命周期内的 verdict 和分享范围缓存；每次相关消息重新解析有效分享。
- 连接建立时保存服务端验证的 sessionId；后续入站消息与数据推送重新读取该会话和有效本地账号。账号删除、停用及系统账号均不作为有效浏览器身份。
- 表或视图通道解析到实际表 ID，用 PermissionService.getPermissionsByResourceId 检查 table|read；数据库通道检查 base|read。
- 增加 ShareDB sendPresence 钩子，已存在的订阅在每次 presence 数据推送前重新鉴权，拒绝时丢弃该次数据，不把错误当作正常数据发送给客户端。
- 服务端进程内连接保留可信路径。合法分享仍可按自身有效范围读取，不因浏览器本地账号退出而把独立公开分享也视为已撤销。
- 保留原有已删除/不存在资源通道的兼容行为；本期不改变其“无实时资源可读”的处理。

本期修复针对 presence（光标、协作成员、通知及已有应用事件通道），不是全部 ShareDB 文档操作流。不会主动关闭整个 socket，也不回收客户端已经收到的数据、取消已经开始的 HTTP 批次或已提交事务。矩阵归属失效只撤销派生授权，不影响独立手工授权。

实时会话、账号及权限检查增加存储读取次数；当前优先保证撤销生效，未做生产吞吐压测或引入带一致性风险的短时鉴权缓存。

## 回归验证

- 新增 10 项 presence 连接生命周期测试：实际连接先订阅，再撤销/恢复权限、会话失效、账号停用、分享关闭、数据推送拦截、仍有效时正常投递及存储故障拒绝。
- 新增 5 项矩阵权限服务集成测试：混合写入双动作校验、目标表单独检查、追加权限撤销、独立手工权限保留及字段/导出权限不扩大。
- 执行既有选区/粘贴、upsert 权限、链接标题新增、对称字段权限及撤销重做权限测试。本期 10 个测试文件、165 项用例通过；后续新增两项 presence 测试后，presence 与矩阵集成的定向复测 2 个文件、41 项通过（其中 presence 共 31 项）。两次结果有重叠，不累计相加。不能把 mock 回归等同真实 v1/v2 数据库端到端验证。

后端全量类型检查仍有其他已有文件报错（输出 363 行），本期修改文件未报告类型错误；oxlint、oxfmt 与 git diff --check 通过。前端没有修改，因此未重复执行前端测试。
